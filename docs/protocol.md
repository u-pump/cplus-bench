# Agent and verifier protocol

1. The curator selects an upstream C/C++ CMake/CTest bug with a precise broken commit, a later fix, and a test added or strengthened by that fix. The curator runs `cplus bug --from-fix` on the broken commit. A case is eligible only when the bug is reproduced. Record the elapsed time separately from any agent run.
2. Freeze the issue title and body as `ISSUE.md`, removing only passages that reveal the solution, and record each removal in the curator report. Export the broken commit with `git -c core.autocrlf=false archive --format=tar <base>`. Add the same `TASK.md` to every input: `Fix the bug described in ISSUE.md. Keep the change minimal. Run the existing tests.` Publish each snapshot as a private `u-pump/bench-in-<id>` repository with one root commit and no upstream history. `input_sha256` is SHA-256 of the raw archive bytes followed by the UTF-8 bytes of `ISSUE.md` and `TASK.md`, in that order. The agent receives only this repository; do not connect the benchmark repository, upstream fix commits or tests, cplus binaries/source, previous results, or curator credentials.
3. Record the agent product, exact model/version, invocation, start time (UTC), input hash, and patch hash in `case.yaml` before judging. Save the first emitted unified diff unchanged as `agent-fix.patch`; no human edits or retries within the same attempt. An empty patch and `agent: null` mean the agent has not run.
4. On the verifier side, reconstruct the upstream base and the upstream fix test, create a BugSpec using `cplus bug --from-fix`, then run `cplus verify --project <base> --patch agent-fix.patch --bug-spec <spec> --json`. The verifier keeps its private logs and source. The public report contains only verdict, the eight check names/statuses, and elapsed time. Failures to clone, build, reproduce, or verify are infrastructure errors, not code verdicts.
5. The owner reviews case provenance and generated results before publishing any aggregate results in README.

## Cloud agent input

The owner connects one private `bench-in-<id>` repository to a separate Codex Cloud environment, with no other repository, secret, or custom setup file attached. Disable outbound internet access for the agent environment, so it cannot look up the upstream repository or fix. Paste the exact `TASK.md` sentence as the first Code task. After the first completed answer, create a PR in that private repository without editing the diff or asking for another attempt. Send the PR link and exact model name to Codex. Codex exports the complete first diff byte for byte into `cases/<id>/agent-fix.patch`, records the agent name, exact model/version, UTC date, PR link, and patch SHA-256 in `case.yaml`, and opens a separate PR in `cplus-bench`. The verifier runs later, outside the agent environment. See [owner steps](run-agent.md).
